\# Security Policy



\## Supported versions



Security fixes are applied on the actively maintained codebase in `develop` and released through `main`.



\## Reporting a vulnerability



If you discover a security issue, please avoid publishing full exploit details in a public issue before the problem is reviewed and fixed.



Suggested process:



1\. Prepare a clear description of the issue.

2\. Include reproduction steps, affected files, and potential impact.

3\. Share the report privately with the maintainer through the preferred repository contact channel.



\## Dependency scanning



This project uses automated dependency scanning in CI with `pip-audit`.



Security scan results are reported as CI artifacts to support review without blocking all test execution.
